# 2026.296.1405 — fix(skills): the k3s skill node's description is the FILE's, not a second copy

## Summary

`charly.yml` carries the `k3s` skill's description TWICE — once inline on the `k3s-skill:` node, once in `.agents/skills/k3s/SKILL.md`'s frontmatter. The two copies are the same prose but not the same VALUE: the node's `|-` block keeps its line breaks, the file's single-quoted scalar folds them into spaces, and the marketplace corpus generator compares the two YAML-parsed values with exact string equality. It therefore refuses the node, and the org-wide corpus generation exits 1.

This change deletes the inline copy — the draining step `/charly-internals:skills` prescribes ("Leave the `skill:` node carrying ROUTING only … Moving a body means DELETING the node's `content:`/`description:` in the same change, never copying the file back over them"). The node keeps the routing the consumers need (`name`, `family`, `owner`); `.agents/skills/k3s/SKILL.md` becomes the single source of record; the published corpus page carries the file's frontmatter. The published prose is the same text the node declared — this change moves no information.
